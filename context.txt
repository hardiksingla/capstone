Purpose & context
Tar is working on their capstone project titled "Behavioral Biometrics Based Integrity Analysis for Online Coding Assessments" (BBIA-OCA), which uses machine learning to detect cheating in online coding assessments by analyzing behavioral patterns. The system addresses a specific cheating scenario where students view pre-written or AI-generated solutions on a second device while typing them into the assessment platform, creating distinctive linear typing patterns that differ from genuine problem-solving behavior.
The project involves a Chrome extension that captures behavioral data during LeetCode sessions, extracting 58 features across six categories (navigation patterns, editing behaviors, typing rhythm, mouse interactions, code evolution, and workflow actions). Machine learning models (Logistic Regression and Linear SVM) are used to distinguish genuine problem-solving from suspicious copying patterns. The system generates suspicion scores and risk levels for instructor review, emphasizing interpretability and transparency in academic integrity decisions.
Key technical constraints include working with a dataset of 158 sessions with 58 features, requiring careful model selection and regularization to prevent overfitting. The project emphasizes practical deployment considerations like microsecond prediction times and minimal computational overhead suitable for educational environments.

Current state
The system has multiple components actively working together. The core Chrome extension captures behavioral events during coding sessions on LeetCode, and the feature extraction pipeline processes this data into 58 behavioral metrics. Both Logistic Regression and Linear SVM models are trained using 5-fold stratified cross-validation with strong regularization (C=0.01) to handle the challenging feature-to-sample ratio.

The dataset consists of 158 real sessions collected manually using the Chrome extension — 64 normal sessions (genuine problem-solving recorded by Hardik) and 94 suspicious sessions (recorded while viewing and typing NeetCode solutions or ChatGPT-generated solutions from a second device). Session filenames reflect their source: normal sessions use prefixes like "real_yLL_hardik", and suspicious sessions use prefixes like "real_sus_neetcodesol*" or "real_sus_chatgpt*". All data is real human behavioral data captured live through the Chrome extension.

The project documentation includes a comprehensive report with natural language writing to avoid AI detection tools, complete with diagrams covering system architecture, data flow, and UML representations. Technical justifications for model choices emphasize the appropriateness of linear models for small datasets and the value of interpretable results in academic settings.

Key learnings & principles
Linear models with strong regularization are specifically designed for high-dimensional, low-sample scenarios and provide crucial interpretability for academic integrity decisions. The feature-to-sample ratio of 1.5:1 makes complex models prone to memorization rather than generalization, while regularized linear models can learn meaningful decision boundaries from limited data.
Using complementary models (Logistic Regression for probability estimation, Linear SVM for margin maximization) provides more robust classification than single complex models. Agreement between models increases confidence, while disagreement flags ambiguous cases requiring human judgment.
The suspicious sessions were generated by Hardik personally — viewing a pre-written solution (from NeetCode or ChatGPT) on a second screen and typing it into LeetCode. This reproduces the exact cheating scenario the system is designed to detect and produces realistic behavioral data with the characteristic linear typing patterns.
Writing in natural, conversational language rather than academic jargon is critical for avoiding AI detection tools while maintaining technical accuracy and professional quality.

Approach & patterns
The development follows a systematic approach starting with data collection through the Chrome extension, followed by feature extraction across six behavioral categories, then model training with careful attention to regularization and cross-validation. The workflow emphasizes interpretability at every stage, from feature selection to final suspicion scoring.
Model evaluation uses stratified 5-fold cross-validation with class-weighted scoring to handle potential class imbalance. The system generates risk levels (LOW/MEDIUM/HIGH/CRITICAL) rather than binary classifications, providing instructors with nuanced information for decision-making.
Documentation and reporting emphasize clear, natural language that avoids AI detection while preserving technical depth and accuracy.

Tools & resources
The technical stack includes a Chrome extension for data collection, Python for feature extraction and machine learning (using scikit-learn for Logistic Regression and Linear SVM), and a React frontend with a Flask backend for the instructor-facing analysis dashboard.
The system uses PlantUML for sequence diagrams and Mermaid.js for other technical documentation and visualization, with diagrams covering system architecture, data flow, and UML representations. Cross-validation and model evaluation rely on stratified sampling techniques appropriate for small datasets.
